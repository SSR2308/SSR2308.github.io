Engineering Process

Both this season's robot and the three before it were built the same repeatable way. Everything in the two case studies below (chassis, then the goal-clamp mechanism) maps directly onto these five stages.

Every subsystem goes through the same five-stage design cycle, documented start to finish in the team's engineering notebook:

  • Identify Problem — define the problem in words/pictures, write a problem statement, set solution requirements.
  • Brainstorm Solutions — generate multiple options with labeled sketches and pros/cons.
  • Select & Plan — score options in a weighted design matrix, then build the winning option in CAD.
  • Build Solution — document parts used and construction steps.
  • Test Solution — run predetermined, numeric tests against the goals from step 1, and loop back if a test fails.

Case Study: Chassis Design

First application of that process: the drivetrain, since nothing else on the robot works if the base doesn't.

Problem

VRC High Stakes required a base that fit an 18"×18"×18" cube, survived driving over rings, and stayed maneuverable — on a maximum of 8 motors.

Selecting a drivetrain

I evaluated five drivetrain architectures, standard 6-wheel omnidirectional, X-drive, mecanum, H-drive, and a hybrid traction/omni layout, against a weighted design matrix scoring speed, maneuverability, traction, strength, and motor strain. The hybrid setup (2 traction wheels center, 4 omni wheels at the corners) won for combining strong forward speed and good turning with none of mecanum's traction problems or X-drive's motor strain.

Both-wheels drive scored highest (8.5) and was selected for the first chassis iteration

CAD and build

The winning layout became a 6-motor, dual 48-tooth-gear chassis (480 RPM drive) built with screw joints instead of drive shafts; fewer parts, more rigidity, less friction, at the cost of longer build time. Two build problems came up mid-construction and got solved on the fly: standard 60-tooth gears aren't compatible with the plastic bushings a screw joint needs, so I hand-drilled a 3/16" bore through each one to mimic the plastic insert; and the 48-tooth high-strength gears needed to be cut in half to fit the compact footprint, which meant hand-hacksawing through a steel-core gear since the bandsaw couldn't handle it.

The final CAD — six motors, screw-joint wheel pods, dual 48-tooth gearing

The gear fix: standard 60-tooth gears drilled to accept a plastic shaft insert

Case Study: Goal Possession Mechanism ("Back Clamp")

The chassis gets the robot around the field, this mechanism is what actually scores. Same process, second subsystem, and this time the design changed mid-season after watching a competitor.

The clamp that secures scoring goals went through two full design iterations. The first version, a pivoting C-channel prong actuated by two pneumatic pistons, won its own weighted design matrix (grip strength, margin of error, speed, weight, reliability) over a simpler C-channel-plus-stub design and a "goal lift" concept, and was built and tested on the robot.

After watching a competitor's design (Team 360X) at competition, I identified three specific improvements worth adopting: an over-center locking linkage that mechanically holds the clamp shut once the pistons retract, wider prong spacing for a larger margin of error when approaching a goal, and reinforced pillow-block-bearing mounts for the pivot. Iteration 2 incorporated all three.

Software

Neither of those mechanisms moves on its own — this is what actually drives them, on the field, during a match.

The autonomous and driver-control stack is built on LemLib (chosen over EZ-Template and VEXcode for its odometry and curvature support), with an Inertial Measurement Unit plus horizontal and vertical tracking wheels for real-time field-position odometry, separately tuned PID controllers for linear and angular motion, exponential input curves on throttle and steering for finer low-speed control, and an arcade-style driver control scheme.

Motor groups & sensor setup:

// motor groups
pros::MotorGroup leftMotors({-11, -13, 15}, pros::MotorGearset::blue);
pros::MotorGroup rightMotors({-16, 19, 20}, pros::MotorGearset::blue);

// inertial sensor
pros::Imu imu(10);

// tracking wheels (odometry)
pros::Rotation horizontalEnc(14);
pros::Rotation verticalEnc(-18);
lemlib::TrackingWheel horizontal(&horizontalEnc, lemlib::Omniwheel::NEW_275, -5.75);
lemlib::TrackingWheel vertical(&verticalEnc, lemlib::Omniwheel::NEW_275, -2.5);

Tuned PID controllers for the drivetrain:

// lateral (forward/back) motion controller
lemlib::ControllerSettings linearController(
    10, 0, 3,     // kP, kI, kD
    3, 1, 100, 3, 500, 20
);

// angular (turning) motion controller
lemlib::ControllerSettings angularController(
    2, 0, 10,     // kP, kI, kD
    3, 1, 100, 3, 500, 0
);
